## 現有機制與真正的缺口

| 工作 | 現況 | 下一步的理由 |
| --- | --- | --- |
| 分割降頻＋光流 | 已依穩定度從間隔 1→2→3；真實量測最大年齡預設 0.1 秒 | 程式仍有 **3 幀硬上限**，`--seg-max-gap` 調到大於 3 不會再增加實際間隔；需先建立更完整的可靠度判斷 |
| 主角優先 | 可放行遠離主角、運動包絡不相交的失效次要追蹤 | 其他仍可見人物的低信心、光流失敗等仍能阻止跳幀；應按干擾主角的風險分級 |
| 背面／遮臉 Pose | cascade 已不要求臉：至少 4 個身體點，其中至少 3 個肩髖點 | 主角 Pose 排程卻需至少 6 個總關鍵點、3 個肩髖點，信心門檻至少 0.5；與 cascade 預設 0.35 不同 |
| 手部異常 | 關鍵點有信心篩選，但手腕／手肘仍參與姿態穩定度 | 應區分可靠軀幹、不可靠手點與真實大幅肢體活動，不能把所有手動作都忽略 |
| Pose 快取 | 保留原推論時間，框改映射不會刷新時間 | `cue_interval` 同時控制更新週期與 cascade 有效期限；延長前應拆開「軟更新」與「硬到期」 |
| 遮罩 | 保存面積、質心、頂部位置等摘要；預測幀只是平移摘要 | 預測摘要不代表新的分割證據，尚無真正的遮罩連續性驗證來支持延長 Pose 快取 |
| 顯著性三級切換 | 已有穩定觀測、降級遲滯、0.35 秒 neural cache 與預設 3 幀冷卻 | 應先減少上游不必要的失效，再調切換；第二人搶鏡時 DeepGaze 可能是正確決策 |
| 離線雙向插值 | 尚未實作；`--lookahead-seconds` 目前只是速度外推 | 使用未來畫面需要新增緩衝或分析／輸出兩階段，不能直接拿現有 lookahead 參數代替 |

## 建議順序

1. **統一證據與失效原因。** 分開評估軀幹、臉與四肢；統一主角 Pose 排程和 cascade 的可信資訊介面，
   依用途保留適當門檻，並非一律降到較低的信心值。新增可追查的原因與真實量測年齡。
2. **補足遮罩連續性，再深化主角排程。** 在真實分割幀比較低解析遮罩／形狀摘要，記錄量測時間。
   區分構圖必要人物、可能搶鏡／交錯的人物、遠處低風險旁人；保留定期全畫面檢查與新人物觸發。
3. **協同調整 YOLO 與 Pose 更新。** 依秒數、光流殘差、量測年齡和不確定性決定間隔；
   先突破無效的排程阻擋，再逐步放寬 3 幀上限。Pose 軟更新可以延後，硬到期不得由預測自行延期。
4. **減少不必要的顯著性切換。** 出現身分疑慮、切鏡、持續遮擋等立即重新評估並按需要升級；
   降到便宜路徑需連續可信證據。沿用可靠身體姿態、便宜顯著性、DeepGaze 的既定次序。
5. **最後增設離線雙向模式。** 前面建立的量測來源、可靠度、切鏡和身分界線可直接共用。
   先評估短視窗緩衝，再決定是否值得做整片分析／二次讀片。

## 背面與手部：具體規則

| 情境 | 建議動作 |
| --- | --- |
| 背面或遮臉，但肩髖、框、追蹤可靠 | 用身體姿態構圖，不要求臉；仍驗證軀幹幾何與量測年齡 |
| 只有手腕／手肘缺失或錯位 | 降低這些點的權重；不直接判整個 Pose 失效。可靠的大幅手動作仍保留裁切警示 |
| 短暫遮擋，近期真實分割與追蹤連續 | 有限時間沿用可靠 Pose，必要時走便宜顯著性；快取保持原始時間 |
| 手靠近鏡頭／局部入鏡，連人物框或身分都受影響 | 降低快取信任，補分割／Pose，資訊不足才用 DeepGaze |
| 長遮擋、暗場、人物交錯、3D 旋轉或明顯動作 | 提早補量測；不能用「中心沒移動」當成穩定證明；保留 DeepGaze 及失效回退 |

主角 ID 延續也需要獨立證據；不因前後框相近或主角鎖定就把新 ID 強接成原 ID。

## 三個可選方案

| 方案 | 範圍 | 可行性與代價 |
| --- | --- | --- |
| **A：穩健增量** | 統一軀幹／手部可靠度、建立真實遮罩連續性、改善主角優先；先保留 gap≤3 與現有快取上限 | 可在現有單遍架構逐步完成，改動風險較低；速度收益取決於目前不必要補偵測的比例 |
| **B：安全自適應（建議）** | A＋分割／Pose 共用可靠度與年齡限制、動態間隔與有限快取延長，再改善三級切換 | 適合目前 170 秒 3D 與固定鏡頭兩類素材；單遍、緩衝可控。需驗證新間隔下的漂移與主角品質 |
| **C：離線關鍵幀＋雙向修正** | 共用 B 的證據判定；由離線調度器選關鍵幀、困難段補偵測、前後修正軌跡，再逐幀輸出 | 技術可行，工程量最大；遮擋／切鏡多時補偵測與 I/O 可能抵銷收益，不保證比 B 快 |

B 的起始候選可評估 **60 FPS 穩定片段由 gap 3→6**，仍受 0.1 秒真實量測硬期限與其他風險條件限制；
這是待驗證候選，並非已支援設定或最終承諾。30 FPS 不能照抄 6 幀；更新時機按來源時間計算。

C 有兩種實作方式：

- **短視窗緩衝**：順序讀片，延後少量影格輸出，使用視窗內前後量測修正。限制緩衝容量，不能把整部 4K 影片留在顯存。
  若只留小圖／量測資訊，輸出所需原始影格仍要緩衝、暫存或重讀，不能假設 I/O 消失。
- **兩遍處理**：第一遍保留量測、軌跡與切鏡資訊；第二遍讀取原圖輸出。較利於長區段修正，但增加解碼與 I/O。
  困難區段可補端點或中點量測；補量測過多時應回到密集偵測，避免只靠插值掩蓋問題。

三個方案皆保留每個來源影格與原 FPS。插值的是人物／構圖目標軌跡，不是生成替代影片幀，
也不把兩個人物遮罩線性混合成新分割結果。

## 可並用與需要避免的衝突

| 組合 | 結論與限制 |
| --- | --- |
| TorchCodec／GPU 前處理＋A／B／C | 相容；一者減少資料搬運，一者減少模型呼叫。總速度收益不能直接相乘 |
| 低頻 YOLO＋運動預測／光流 | 相容且已有基礎；現有 LK 主要估平移，3D 旋轉、縮放或交錯可能合理回退偵測 |
| 分割跳幀＋Pose／DeepGaze 快取 | 可並用，但須共同限制觀測不足；各自保留真實量測時間、場景與身分來源。新 Pose 不刷新舊分割，光流不刷新 Pose |
| 主角優先＋全畫面監視 | 相容；遠處失效旁人可較低優先，但新入鏡、靠近主角與搶鏡的人仍需處理 |
| 離線插值＋單遍因果預測 | 共用量測及可靠度；同段軌跡只能由一個調度器主導，避免重複補偵測或兩套預測互相改寫 |
| 雙向插值＋切鏡／身分不明／長遮擋 | 不可直接跨界連線。兩端必須同場景、身分可信；光線漸暗也不代表 ID 可安全延續 |
| 降低 YOLO 頻率＋DeepGaze MR | 相容，但 MR 的 16 幀時間窗口仍按來源順序觀測，不能偷換成 16 張稀疏關鍵幀 |

評估總耗時需同時看解碼、前處理／排程、模型呼叫、構圖、輸出與初始化。
模型時間約隨呼叫數下降，但額外光流、遮罩比較、同步、緩衝與重讀成本可能抵銷收益。
目前沒有這些新方案的 T4 實測，不能預告加速倍數或宣稱無 GPU 風險。

## 參數精簡建議（待選，這次不移除）

| 處理方式 | 現有參數 | 建議 |
| --- | --- | --- |
| 先棄用，再移除 | `--saliency-trust-repo` | 現在只保留相容用途，載入器不讀取該值。先停止在新範例產生此旗標、舊命令仍接受，後續版本再移除 |
| 統一秒數入口 | `--motion-response`＋`--motion-damping` → `--pan-time`；zoom 對應兩項 → `--zoom-time` | 目前已先換算成 time 才使用；不是仍有兩個獨立控制。保留舊命令轉換，明確指定新參數優先 |
| 統一時間／速度入口 | `--target-alpha` → `--target-time`；`--zoom-alpha` → `--zoom-speed`；`--max-step-x/y` → `--pan-speed-x/y` | 舊值仍有作用，不能直接刪而不遷移。x/y 覆寫有用途，不強制合成同一速度 |
| 統一 hold 的單位 | `--max-missed-frames` → `--lost-hold-seconds`；`--min-subject-hold-frames` → `--subject-hold-seconds` | 舊參數以 30 FPS 參考值換算，容易誤解。lost 與 subject hold 功能不同，保留兩個秒數控制 |
| 用 profile 管理 | `--seg-max-gap`、`--seg-max-age`、`--cue-interval`、`--saliency-interval` | 可以用一個追蹤 profile 展開多個設定；不能合成同一個 interval。分割幀數／秒數限制、Pose 期限、DeepGaze 冷卻各有不同作用 |
| 簡化資料流入口 | `--video-decoder`、`--frame-processing`、`--decode-device` | 可新增 `--pipeline reference/decode/tensor` 預設組合；保留進階裝置覆寫。tensor 需 TorchCodec，解碼、YOLO、DeepGaze 裝置不必相同 |
| 保留 A/B 診斷 | `--seg-thumbnail-mode/method`、`--seg-skip-policy`、scene／encoder／debug 參數 | 仍有實際分支，T4 尚待驗證，先移入進階說明，不急著刪除基準路徑 |
| 不合併 | `--conf`、`--pose-conf`、`--keypoint-conf`；解碼／Pose 的 batch size | 分別是不同模型信心與不同工作批次；一個值無法表達各自的精度、顯存和效能需求 |
| 保留使用者控制 | `--dead-zone`、`--zoom-dead-zone`、`--zoom-hold-seconds`、`--fixed-zoom`、`--precrop`、`--post-restore` | 平移、縮放、推論區域與後處理是不同決策。dead-zone 預設 0；post-restore 已預設關閉 |

建議先做「相容棄用＋秒數／速度參數」；選 B 時再加入 **`--tracking-profile conservative/balanced/fast`**。
profile 名稱是提案，目前 CLI 不接受。它只管理推論排程，不取代既有 `--preset talking_head/sports/pets/cars`。
資料流 profile 與追蹤 profile 可組合，顯式進階參數優先，Summary 記錄展開後有效設定。
camera profile 可以後續再評估，不必一次新增第三組模式；任何 profile 都不應默默把 dead-zone 從 0 改回非零。

## 本輪已實作：dead-zone 預設 0

- 全部 preset、不指定 preset、直接建立 AppConfig 皆預設 0；明確指定非零值仍生效。
- `benchmark_colab.py` 與 `colab_torchcodec.py` 同步預設 0，可用 `--dead-zone 0.06` 重現舊設定。
- Summary 記錄平移／縮放 dead zone；TorchCodec 續作辨識包含 dead-zone，改值後不能沿用舊測試成功紀錄。
- 0 代表取消非零平移死區，並不關閉相機平滑、速度限制或變焦死區。這是構圖偏好變更，不是模型加速。
- 新舊速度與畫質比較必須對齊 dead-zone，避免把構圖差異誤判成推論優化回歸。

## 驗證與續作

先等選定 A／B／C 及參數精簡範圍，再依上方順序分段提交。每段保存邏輯測試與 T4 待驗證事項；
集中測試時只需最終版本和相關基準，不預設把所有中間版本各跑完整長片。

現有每五秒 Segment 已能比較 YOLO 真實偵測／預測幀、間隔分布、Pose ROI、DeepGaze 呼叫與原因、主角切換和分段耗時。
後續需另增軀幹／手部失效原因、Pose／分割真實年齡分布、遮罩量測來源與補偵測原因；這些欄位目前尚未齊備。
最終同時看成片主角／裁切品質、總速度、顯存與輸出幀數／音訊尾端；DeepGaze 呼叫越少不等於品質越好。
